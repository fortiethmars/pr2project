# Проверка этапа 2 — общий бизнес-слой и тесты ограничений

## Что реализовано

- Общие доменные модели для подразделений, сотрудников, рабочих сессий и параметров отчёта.
- Проверка руководителя подразделения: он должен существовать и принадлежать этому подразделению.
- Проверка правил сотрудника: непустое ФИО, существующее подразделение, обязательный руководитель для всех кроме корневого руководителя, запрет самоподчинения, кабинет должен входить в список доступных помещений.
- Проверка единственного корневого руководителя.
- Поиск циклов в дереве подразделений и иерархии подчинения.
- Расчёт рабочих часов по пересечению закрытых рабочих сессий с выбранным периодом. Незакрытые сессии не включаются.
- Формирование отчёта: только явно выбранные подразделения, не менее трёх прямых подчинённых по умолчанию, доступ минимум к двум помещениям из выбранного списка; фильтр по часам необязателен.
- Автоматизированные unit-тесты на перечисленные ограничения и расчёт отчёта.

## Границы текущей реализации

Это бизнес-слой и unit-тесты, работающие без запущенного PostgreSQL. Здесь пока нет интеграции с реальной БД, транзакционного репозитория или маршрутов FastAPI. Поэтому тесты проверяют правила бизнес-слоя, а не поведение PostgreSQL и не HTTP API. Это будет следующим отдельным шагом после проверки.

## Запуск тестов

Из корня проекта:

```bash
python -m pip install pytest
python -m pytest -q
```

Ожидается 13 тестов. Тесты должны завершиться успешно.

## На что обратить внимание при проверке

1. Открытые рабочие сессии исключаются из подсчёта часов.
2. Сотрудник проходит фильтр помещений, только если имеет доступ как минимум к двум помещениям из выбранного списка.
3. Считаются только прямые подчинённые.
4. Отчёт не включает дочерние подразделения автоматически: проверяется только точное совпадение с выбранными ID.
5. Для создания подразделения и его руководителя в одной транзакции позже потребуется аккуратно реализовать отложенные внешние ключи и резервирование ID; этот механизм ещё не реализован.
