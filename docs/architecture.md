# Архитектура практической работы №2

## Принятые решения

- Настольный клиент: Python + PyQt6.
- Веб-клиент: Python + FastAPI + HTML/CSS (шаблоны Jinja2).
- Централизованная БД: PostgreSQL.
- Клиенты работают по локальной сети и не подключаются к PostgreSQL напрямую: оба обращаются к серверному API. Для настольного приложения это сохраняет единые правила проверки и отчёта.
- Интерфейс на русском языке.
- Авторизация не реализуется по согласованию пользователя; сервер предназначен для доверенной учебной локальной сети. Это не следует считать безопасной конфигурацией для открытого интернета.

## Данные

1. `department_types` — типы подразделений.
2. `departments` — подразделения с родительской ссылкой и обязательным руководителем.
3. `employee_types` — типы сотрудников.
4. `employees` — сотрудники, одно основное подразделение, начальник и кабинет.
5. `rooms` — помещения.
6. `employee_room_access` — права доступа сотрудников к помещениям.
7. `work_sessions` — рабочие сессии с началом и необязательным окончанием.

## Правила отчёта

- Пользователь обязан выбрать хотя бы одно подразделение и одно помещение.
- Отбираются только сотрудники из явно выбранных подразделений, без автоматического включения дочерних подразделений.
- У сотрудника должно быть не менее трёх прямых подчинённых.
- Сотрудник должен иметь доступ как минимум к двум помещениям из выбранного списка.
- Фильтр по минимальным рабочим часам необязателен.
- Если фильтр часов включён, суммируется только пересечение закрытых рабочих сессий с выбранным периодом.
- Начало и конец периода задаются пользователем; по умолчанию UI предложит предыдущий календарный месяц.

## Ограничения и проверки

- Тип сотрудника и подразделение обязательны.
- У подразделения должен быть руководитель, который принадлежит этому же подразделению.
- У каждого сотрудника есть начальник, кроме корневого руководителя организации.
- В организации допускается не более одного корневого руководителя; проверка наличия ровно одного будет выполняться на уровне бизнес-логики/валидации состояния.
- Нельзя назначить сотрудника начальником самому себе или подразделение собственным родителем.
- Циклы в иерархиях сотрудников и подразделений должны отклоняться сервисом до сохранения.
- Если назначен рабочий кабинет, у сотрудника обязательно есть право доступа к этому помещению.
- У сотрудника не более одной незавершённой рабочей сессии.
- Время окончания не может быть раньше времени начала.
- Удаление связанных записей не должно приводить к потере истории или нарушению ссылок.

## Этапы

1. Схема БД и каркас — текущий этап.
2. Общий слой бизнес-логики и тесты ограничений.
3. Веб-приложение FastAPI.
4. Настольное приложение PyQt.
5. Отчёт, диаграммы, скриншоты и проверка сценариев преподавателя.
