# Этап 1 — результат для проверки

## Что подготовлено

- Черновая схема PostgreSQL из семи таблиц.
- Внешние ключи и уникальные ограничения.
- Ограничение на руководителя подразделения из того же подразделения.
- Ограничение, по которому рабочий кабинет должен присутствовать в списке доступов.
- Частичный уникальный индекс для одной незавершённой сессии сотрудника.
- Проверка порядка начала и окончания сессии.
- Каркас каталогов и документация архитектуры.

## Что ещё не реализовано

- Не запускали SQL против сервера PostgreSQL: в текущей среде нет доступной команды `psql`/локального PostgreSQL.
- Не реализованы сервисные проверки циклов в иерархиях.
- Не реализована проверка наличия ровно одного корневого руководителя (БД пока запрещает больше одного).
- Нет API, окон PyQt и веб-форм — это следующие этапы.
- Диаграммы пока концептуальные и нуждаются в окончательном оформлении для сдачи.

## Вопросы на проверку

1. Подтвердить, что общая схема из семи таблиц и PostgreSQL подходит.
2. Подтвердить, что оба клиента будут работать через FastAPI API, а не подключаться к PostgreSQL напрямую.
3. Подтвердить, что на данном этапе можно перейти к реализации общего слоя бизнес-логики и тестов после проверки SQL на реальном PostgreSQL.
