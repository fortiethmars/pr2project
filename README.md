# Практическая работа №2 — учёт оргштатной структуры предприятия

## Текущий этап

Подготовлен первый этап: предварительная схема PostgreSQL, структура каталогов и документация архитектуры. Полноценные интерфейсы PyQt и FastAPI будут реализовываться следующими этапами после проверки этого фундамента.

## Состав

- `database/001_schema.sql` — таблицы, внешние ключи, ограничения и индексы PostgreSQL.
- `docs/architecture.md` — согласованная архитектура и бизнес-правила.
- `docs/diagrams.md` — исходники диаграмм для последующего оформления.
- `desktop/` — настольный клиент PyQt (следующий этап).
- `webapp/` — веб-приложение FastAPI (следующий этап).
- `shared/` — общий слой доступа к данным и бизнес-логики (следующий этап).
- `.env.example` — пример конфигурации подключения.
- `requirements.txt` — зависимости Python.

## Требования

- Python 3.11 или новее.
- PostgreSQL 15 или новее.
- Windows 10/11 для клиентских приложений.

## Создание базы

1. Установить PostgreSQL и создать базу `pr2_enterprise`.
2. Выполнить SQL-файл `database/001_schema.sql` в этой базе от имени пользователя, имеющего право создавать таблицы и индексы.
3. Скопировать `.env.example` в `.env` и заполнить параметры подключения.
4. Установить зависимости командой `python -m pip install -r requirements.txt`.

ВНИМАНИЕ: SQL-файл рассчитан на новую пустую базу данных и пока не является миграцией для уже существующей схемы.

## Важное замечание по ограничениям

Схема уже обеспечивает внешние ключи, обязательность основных ссылок, принадлежность руководителя подразделению, доступ к назначенному рабочему кабинету, уникальность незавершённой сессии и корректность временного диапазона. Проверки циклов в иерархиях и наличие ровно одного корневого руководителя будут дополнительно реализованы и покрыты тестами в общем бизнес-слое. Уникальный частичный индекс не допускает более одного корневого руководителя, но сам по себе не гарантирует наличие хотя бы одного.

## Этап 2: бизнес-слой и тесты

Общие правила предметной области находятся в `shared/domain.py` и `shared/workflow.py`.
Автоматизированные unit-тесты расположены в `tests/` и запускаются командой `python -m pytest -q`.
Отчёт о текущем этапе и его ограничениях: `docs/stage2-review.md`.

## Этап 3: запуск API

1. Создайте пустую базу PostgreSQL и пользователя согласно `.env.example`.
2. Создайте файл `.env` на основе `.env.example` и задайте `DATABASE_URL`.
3. Установите зависимости: `python -m pip install -r requirements.txt`.
4. Примените SQL-схему к новой базе: `psql "$DATABASE_URL" -f database/001_schema.sql` (если ваша утилита `psql` не понимает SQLAlchemy-URL, укажите обычный PostgreSQL connection string).
5. Запустите API из корня проекта: `uvicorn webapp.main:app --host 0.0.0.0 --port 8000`.
6. Документация API доступна по адресу `http://127.0.0.1:8000/docs`.

Реализованные маршруты этапа 3:
- `GET /api/health` — проверка доступности API;
- `GET/POST /api/reference/employee-types` — просмотр и добавление типов сотрудников;
- `GET/POST /api/rooms` — просмотр и добавление помещений;
- `GET /api/departments` и `GET /api/employees` — чтение справочников;
- `POST /api/reports/employees` — формирование отчёта через общий бизнес-слой.

API не создаёт таблицы автоматически: структура должна быть применена из `database/001_schema.sql`. Аутентификация не добавлена в соответствии с согласованным учебным вариантом без авторизации; не публикуйте такой сервис в интернете.
