## 📖 О проекте

**«Мама Птица»** — веб-приложение для централизованного управления информацией о предприятии.
Система позволяет работать с данными сотрудников, формировать организационную структуру, вести учёт помещений и рабочего времени, а также получать отчёты на основе данных базы.
Интерфейс выполнен в тёмной цветовой схеме и разделён на отдельные страницы для удобной навигации.

## ✨ Возможности



### Главная страница

- Просмотр общей статистики предприятия.
- Отображение последних добавленных сотрудников.
- Просмотр распределения сотрудников по подразделениям.
- Отображение количества открытых рабочих сессий.
- Индикация состояния загрузки данных.



### Управление сотрудниками

- Получение списка сотрудников.
- Добавление новых сотрудников.
- Хранение информации о должностной принадлежности и подразделении.
- Связь сотрудников с руководителями.
- Учёт закреплённых помещений.



### Управление подразделениями

- Просмотр списка подразделений.
- Создание подразделений.
- Назначение руководителя подразделения.
- Хранение информации об организационной структуре.



### Управление помещениями

- Просмотр списка помещений.
- Добавление помещений.
- Хранение названий и описаний.
- Поиск помещений по доступным текстовым полям.



### Учёт рабочего времени

- Регистрация начала рабочей сессии.
- Завершение рабочей сессии.
- Получение записей рабочего времени.
- Расчёт продолжительности работы для отчётности.



### Отчёты

- Формирование отчётов по сотрудникам.
- Фильтрация по заданным критериям.
- Анализ количества непосредственных подчинённых.
- Учёт доступа к помещениям.
- Расчёт отработанного времени за период.
- Экспорт результатов в JSON.

## 💻 Требования

Для запуска проекта необходимы:

- Windows 10/11 или совместимая операционная система.
- Python 3.12 или совместимая версия.

- Настроенное окружение приложения.



## 🚀 Установка и запуск



### 1. Клонирование репозитория

```bash
git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ>
cd <ИМЯ_РЕПОЗИТОРИЯ>
```



### 2. Создание виртуального окружения

Для Windows PowerShell:

```powershell
python -m venv .venv
```



### 3. Установка зависимостей

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```



### 4. Настройка конфигурации

Создайте файл `.env` на основе `.env.example`:

```powershell
Copy-Item .env.example .env
```

Укажите параметры подключения к PostgreSQL и другие необходимые настройки в соответствии с конфигурацией проекта.
**Не публикуйте файл** `.env` **в открытом репозитории:** он может содержать пароли и другие секретные данные.

### 5. Подготовка базы данных

Установите и запустите PostgreSQL. Создайте базу данных и пользователя, необходимые приложению.
Примените схему базы данных или выполните предусмотренные проектом миграции. Конкретный способ инициализации зависит от файлов конфигурации и схемы, включённых в репозиторий.

### 6. Запуск сервера

Из корневого каталога проекта выполните:

```powershell
.\.venv\Scripts\python.exe -m uvicorn webapp.main:app --host 127.0.0.1 --port 8001
```

После успешного запуска приложение будет доступно на локальном сервере по адресу: **[http://127.0.0.1:8001/](http://127.0.0.1:8001/**)**  
Для всех пользователей другой адрес:  

[https://silent-storm-2990da4c.tunnl.gg/](https://silent-storm-2990da4c.tunnl.gg/)

## 🗄 База данных

В качестве СУБД используется PostgreSQL.
База данных хранит информацию об основных сущностях приложения:

- сотрудниках;
- типах сотрудников;
- подразделениях;
- типах подразделений;
- помещениях;
- доступах сотрудников к помещениям;
- рабочих сессиях.
Связи между сущностями позволяют формировать организационную структуру и использовать данные в отчётах.
Остановка веб-сервера не должна удалять существующие записи PostgreSQL



## 🔐 Безопасность

- Не добавляйте `.env` в публичный репозиторий.
- Не публикуйте пароли, токены и строки подключения с секретными данными.
- Не используйте реальные персональные данные сотрудников в публичных демонстрациях.
- Не открывайте приложение в интернет без необходимой настройки авторизации и контроля доступа.
- Используйте тестовую базу данных для разработки и демонстрации.
- Перед публикацией проверяйте состав файлов, добавляемых в Git.
Для локальной разработки рекомендуется использовать адрес `127.0.0.1`.



## 🧪 Проверка работоспособности

Перед демонстрацией рекомендуется проверить:

- запуск приложения и подключение к PostgreSQL;
